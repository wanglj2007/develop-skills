# Salar-web 前端功能开发

## 适用范围与页面结构

适用于 Salar-web 的业务管理页面。沿用项目的 Vue 3 Composition API、TypeScript、Element Plus、UnoCSS 和国际化体系；不把用户管理的字段、权限或关联关系复制到其他业务域。

开始前阅读目标项目的开发约定，检查当前业务和相邻模块。特殊业务要求与项目明确约定优先。

业务管理功能采用以下职责划分，按实际需求组合：

| 功能单元 | 职责 |
| --- | --- |
| 列表页 | 搜索、分页表格、工具栏、选择状态和行操作 |
| 树形表格 | 层级展示、节点展开、树节点操作与父级选择 |
| 编辑抽屉 | 新增与编辑共用表单、详情加载、校验与保存 |
| 关联编辑器 | 关联数据的本地增删和选择入口 |
| 关联选择弹窗 | 分页搜索、排除已有项、勾选和结果回传 |
| API 封装 | 集中声明请求函数，复用统一请求客户端与错误处理 |
| API 类型 | 分离查询、列表、详情、保存与关联数据类型 |
| 公共 hooks | 复用分页、表格操作和表单校验行为 |

后端接口规则已汇总在本技能的“后端接口契约”中，可直接用于前端对接。

## 版本维护

使用语义化版本：兼容性修正递增补丁号，兼容的新规则递增次版本号，改变接口或实施规则且不兼容旧用法时递增主版本号。版本描述技能规则的变化，不代表目标项目依赖版本或生产验收状态。

## 使用前核对

本技能中的组件参数、hook 名称与尺寸是项目约定的总结。实施前核对目标项目当前组件的 props、事件、插槽、hook 返回值和请求包装；实现已变化时以当前代码为准，不向组件传入不存在的参数，也不为套用本技能修改无关公共行为。

区分接口与数据规则、公共组件实际能力和视觉默认值：接口必须与后端确认，组件按当前实现调用，尺寸与排版按业务内容和视口调整。发现差异时说明采用的实现与影响范围。

## 权限与业务限制

- 沿用项目现有的权限标识、路由守卫、指令或权限判断函数，不自行发明权限命名和授权机制。先明确查看、新增、编辑、删除、启禁用与关联修改各自所需权限。
- 页面访问、菜单可见性和操作按钮分别接入对应权限；直接访问路由也必须经过现有守卫。菜单隐藏不能替代页面访问控制。
- 无操作权限时按项目约定隐藏或禁用入口；事件处理函数也核对权限与记录业务状态，覆盖快捷入口、下拉菜单和批量操作。
- 公共工具栏无法表达分项权限时，使用其插槽按权限构造按钮，不假定隐藏某个按钮会限制其默认事件。
- 系统内置、受引用等受保护记录使用表格的 selectable 等机制限制选择，并在批量提交前重新校验选中集合，不能只隐藏行按钮。不要静默跳过不可操作记录；需要过滤时明确告知范围。
- 权限与业务限制由后端最终校验。鉴权失败沿用请求层反馈，不提示操作成功；前端校验只用于正确的交互和减少无效请求。

## 文件组织与类型

按现有业务归属组织页面、业务子组件、API 封装与类型声明，使用对应业务名称，保持目录职责一致。

- 页面入口负责列表与交互编排，表单和关联交互拆为业务子组件；简单功能无需预建无用组件。
- 使用 `<script setup lang="ts">`；表格列需要 JSX formatter 时使用 `lang="tsx"`。使用 `defineOptions` 声明唯一组件名。
- API 函数通过项目统一的 API 入口导出，内部复用现有请求客户端，不在页面中直接创建请求客户端。
- 分别定义查询、列表项、分页结果、编辑详情与保存请求类型。沿用 `Api.Framework` 等实际命名空间与 `Common.PaginatingQueryRecord<T>` 等公共类型，避免新增 `any`。
- ID 类型与后端一致，不把数字主键统一转换为字符串。保存请求仅包含契约允许的字段，不直接提交含展示字段的完整详情对象。

### 字段校验与数据转换

- 必填、长度、范围、格式与条件校验依据后端模型和业务要求定义；可选字段不强制填写。服务端返回的字段错误映射到表单，保留输入并定位首个错误。
- 明确省略、`null`、空字符串和空数组的含义。编辑时清空字段或全部移除关联，必须发送契约要求的清空值，不能因省略字段而保留旧数据。
- 日期和时间明确格式、时区与范围边界；金额和其他精确数值遵循后端精度约定。超出 JavaScript 安全整数范围的标识或数值使用契约约定的字符串表示，不强制转为 Number。
- 不对密码等敏感输入统一 trim，也不对可选布尔值和数值使用 truthy 判断；业务需要规范化的字段单独处理。

## 列表页

- 复用 `SearchPanel`、`TableHeaderOperation`、`useUIPaginatedTable`、`defaultTransform` 与 `useTableOperate`，先核对当前 hook 签名再接入。
- 查询参数采用项目的 `current`、`size`；默认 `current: 1, size: 50`，可按业务需求调整。未填写的筛选项保持 `undefined` 等契约约定的空值，布尔值 `false` 不得被当作未填写。
- 搜索、回车搜索和重置回到第一页；分页变化同步查询参数。重置同时恢复筛选条件与页码。
- 列定义包含业务需要的选择列、序号、展示字段、状态和操作列。沿用 `$t` 标签、`ElTag` 状态；操作列参考角色管理，圆形编辑图标入口配合 `ElDropdown trigger="hover" size="small"`，选择菜单项后通过 `command` 分派操作，入口本身不直接执行编辑。
- `ElTable` 配置稳定的 `row-key`、加载态和选择事件；将选中记录映射为 ID 数组。空选择时禁用批量操作。
- 启用、禁用和删除先确认；取消确认不发请求。受保护记录按业务规则限制行操作与批量选择，不能仅隐藏单行按钮。
- 启用、禁用等记录状态由表格操作列的按钮或下拉菜单项管理，根据当前状态显示对应操作，调用独立状态接口，成功后刷新表格。
- 请求成功后才调用 `onDeleted`、`onBatchDeleted` 或刷新方法。核对 hook 是否已处理选择清理、删除末页最后一条后的回退与页码越界；已处理则复用，未处理则补齐。
- 搜索和重置回第一页，编辑和状态切换通常保留当前页，新增按业务决定定位。检查 `getData` 与 `getDataByPage` 的实际行为，不因方法名称相似而意外重置页码。
- 只提供业务需要且后端支持的排序；服务端分页不能仅对当前页做排序而声称全量排序。

## 异步请求与状态一致性

- 列表搜索、翻页、树查询、详情和选择弹窗查询都要处理请求竞态。先核对公共 hook 是否已保证最新结果；没有保障时使用请求序号、会话标识或请求客户端支持的取消机制，避免重复实现。
- 每次查询使用确定的参数快照。新请求开始后，旧请求不能覆盖数据、分页总数、错误状态或关闭新请求的 loading；仅当前请求在结束时更新这些状态。
- 快速修改条件时允许最新查询生效，不能用全局 loading 拦截后直接丢弃新条件。重复的相同查询可合并，输入联想搜索可按需求防抖。
- 抽屉、弹窗关闭、切换记录或组件卸载时，使旧请求失效；重新打开使用新的会话标识。过期回调不得更新当前草稿、关闭新抽屉或触发针对新记录的提示。
- 保存、删除和状态切换按对应操作设置提交锁，在异步校验开始前取得保存锁，并在校验失败或请求结束时释放；不能只在请求发出后加锁。批量操作提交选中 ID 的快照。
- 不自动重试写入请求。网络超时不能证明写入失败，先核对服务端结果或使用已有幂等机制，避免重复创建或删除。
- 区分写入成功与刷新失败：保存成功后刷新列表失败，只提示刷新问题，不误报保存失败或再次提交。请求取消与确认取消正常退出，实际错误仍交由统一错误处理。

## SearchPanel 搜索面板

业务列表与树形表格统一复用 `SearchPanel`，由面板负责折叠、表单容器和搜索按钮，页面负责查询状态与数据加载。

| 参数或事件 | 约定 |
| --- | --- |
| `model` | 必传查询对象，与筛选控件绑定同一份状态；不是自动重置或查询的触发器 |
| `collapse-name` | 必传且稳定的业务标识，在当前页面内保持唯一 |
| `expanded` | 默认 `false`；常用管理页面显式设置为初始展开。当前实现只用它初始化折叠状态，不视为双向受控参数 |
| `action-lg` | 默认 `12`，表示大屏按钮区占 24 栅格中的份数；按最后一行剩余空间调整，例如 `18` |
| `title` | 默认使用 `common.search`；自定义标题传入已国际化的文本 |
| `label-width` | 默认 `80`；同一搜索面板保持一致，较长标签按语言和内容调整 |
| `search` | 页面执行查询并回到第一页 |
| `reset` | 页面恢复筛选默认值和第一页，再执行查询；面板仅发事件，不修改模型 |

- 面板使用卡片包裹折叠区域，卡片 body 水平内边距 `16px`、垂直内边距 `4px`，内部表单栅格间距 `24px`。复用现有组件样式，无需在各页面重写。
- 字体继承项目全局的系统无衬线字体栈（`ui-sans-serif`、`system-ui` 等），不单独指定字体。折叠标题通过全局 `html .el-collapse` 的 `--el-collapse-header-font-size: 16px` 设置字号；搜索字段标签、默认尺寸输入框与选择器沿用 Element Plus 的基础字号（当前为 `14px`），搜索和重置按钮因 `size="small"` 使用 `12px`。不要把整个面板统一设为 `16px`，也不要按 Element Plus 原始折叠标题的 `13px` 总结项目样式。核对样式时同时阅读 `src/styles/css/reset.css`、`global.css` 和 `src/styles/scss/element-plus.scss`，不能只看组件模板。
- 默认插槽直接提供 `ElCol` 与其内部的 `ElFormItem`，不重复嵌套 `ElForm` 或 `ElRow`。搜索表单沿用面板的横向标签，编辑表单才使用顶部标签。
- 常规筛选项大屏可设置 `:lg="6"`，一行最多四项；中小屏按字段长度设置 `md`、`sm`、`xs`，窄屏可采用 `:xs="24"`。长字段适当加宽。
- 操作区在中小屏占整行，按钮靠右排列；大屏通过 `action-lg` 控制位置。字段与按钮的栅格总数超过 24 时自然换行，不靠固定像素定位。
- 输入框按需开启 `clearable`，下拉框的布尔或枚举值保持实际类型。占位符和标签使用业务国际化文案。
- 搜索按钮点击与表单提交都触发 `search`。需要 `@keyup.enter` 的控件复用同一查询函数；核对 Enter 是否同时触发表单提交，避免重复请求，不另建一套查询逻辑。
- 重置优先使用统一的默认查询工厂，保持初始状态与重置状态一致。搜索和重置都应清理失效选择，树形搜索遵循祖先保留规则。
- 当前面板未提供独立的 `loading` 或 `disabled` 参数；不要假定传入这些属性就能控制内部按钮。需要请求期间防重复查询时，在页面处理函数中控制，或按任务范围扩展公共组件。

## 树形表格

菜单、组织等具有父子关系的业务使用树形表格；查询、工具栏与请求处理沿用列表页规则，层级展示按以下约定实现。

- 节点类型包含稳定且全树唯一的主键、父级标识和 `children` 子节点集合。使用 `row-key="id"` 与 `tree-props="{ children: 'children' }"`，不要将树平铺后丢失层级。
- 默认采用 `default-expand-all`，层级缩进可设为 `20`。大树按需求改为受控展开或懒加载；仅在提供实际交互时添加展开、收起工具栏，避免默认展开属性与受控状态冲突。
- 首个业务列显示节点名称，保留展开箭头与缩进空间；需要图标时复用 `SvgIcon`，图标约 `16px`，名称与图标间距约 `8px`，图标不被压缩。
- 节点类型、启用状态和可见性使用带文案的语义标签；顺序字段单独展示。编码、路由等较长字段左对齐，按内容设置列宽，必要时使用溢出提示。
- 列较多时操作列 `fixed: 'right'`，居中显示紧凑的下拉操作，确保横向滚动时仍可编辑或删除。
- 树结构不直接套用普通记录分页。完整树不显示分页器；若后端分页，明确按根节点分页还是返回搜索子树，并保证当前结果含所需祖先与子节点，不能把任意一页当作完整树。复用分页 hook 时也要核对它是否截断了树数据。
- 搜索按后端契约返回匹配树或保留祖先链的子树。前端过滤时递归保留命中节点及必要祖先；重置恢复原始树。筛选结果不作为完整的父级选项来源。
- 不假定父节点勾选会自动选择全部后代；按业务明确父子选择是否联动，提交前对实际选中 ID 去重。刷新后清理失效选择。
- 删除父节点前，确认文案必须说明后端实际行为：连同后代删除、禁止删除有子节点的记录，或其他明确规则。批量删除也说明层级影响，父子同时选中时遵循后端的去重与级联规则。
- 新增、编辑成功后重新加载树，以更新节点位置、名称与顺序。编辑仍按 ID 加载独立详情，不能将树节点直接作为完整表单数据。

### 父级选择与条件表单

- 父级选项提供顶层入口，根节点标识由后端契约确定，不硬编码特定业务的根 ID。
- 从完整的可选树递归生成父级选项，只保留业务允许作为父级的节点类型；可用缩进标签或树选择器表达层级。
- 编辑时排除当前节点及其整棵子树，允许选择合法祖先，避免自引用和循环。后端仍须校验层级关系。
- 目录与页面等节点类型分别控制字段显示、必填规则与保存内容；若编辑态禁止改变类型，禁用对应选择控件。
- 隐藏或失效的字段在保存时按契约清空或忽略，不能因控件不可见而提交旧值。界面辅助字段先剔除，再构造保存请求。
- 图标来源切换时清空互斥字段。自动生成的字段设为只读；初始化详情时避免字段监听覆盖已保存值。

## 新增与编辑抽屉

- 抽屉只编辑业务资料，不提供启用、禁用等记录状态的编辑控件；状态变更统一由表格操作列处理。保存表单不承担状态切换，保存请求中的状态字段仅在后端契约要求时按约定处理。
- 新增和编辑共用业务编辑抽屉组件，接收 `operateType` 与当前记录标识，使用 `defineModel<boolean>('visible')` 控制显隐，通过 `submitted` 通知父页面刷新。
- 每次打开新增抽屉，重新初始化模型、关联集合和校验状态，避免上次编辑内容残留。
- 打开编辑抽屉时，只从列表行取得 ID 和必要的界面状态，按 ID 请求独立的编辑详情。表单字段与关联数据必须来自详情接口，不能用列表行填充表单。
- 详情加载期间禁用保存；加载失败时关闭抽屉或展示可重试的错误状态，不允许保存旧数据。快速切换记录时避免较早请求覆盖当前模型。
- 复用 `useForm`、`useFormRules`，让 `ElFormItem.prop` 与模型字段、校验规则一致。不可修改的业务标识在编辑态设为只读，并依赖后端继续校验。
- 密码等敏感字段不回填。只有类似用户管理的业务才应用“编辑密码留空表示不修改”等规则，并核对后端契约。
- 默认参考角色、用户编辑抽屉：在 `ElDrawer` 的 `#header` 插槽中使用 `w-full flex items-center justify-between pr-24px`，左侧标题、右侧保存；保存按钮为 `type="primary" size="small" :loading="saving"`，外包 `ElPopconfirm`，确认文案使用 `$t('common.confirmSave')`，仅在 `@confirm` 中调用提交函数。保留抽屉默认头部与内置右上角关闭按钮，不再额外添加关闭按钮，不把保存放到页脚。提交前校验；按“异步请求与状态一致性”的规则用 `saving` 覆盖校验和请求阶段，在 `finally` 中释放加载态。
- 提交时从本地关联集合生成 ID 数组，显式构造保存请求。成功后提示、关闭并触发 `submitted`；失败时保留输入，沿用请求层的错误提示，避免重复弹错。

### 未保存修改与关闭

- 初始化完成后保存独立的表单与关联草稿基线，按可保存字段判断是否修改；详情加载、默认值初始化和界面辅助状态不计为用户修改。
- 有未保存修改时，关闭按钮、遮罩、Esc、父页面切换等可用离开入口统一走关闭保护；确认放弃后才清理草稿，取消确认继续编辑。无修改时直接关闭。
- 优先复用项目既有的离开保护。注意抽屉 before-close 不一定覆盖自定义按钮或父组件直接修改 visible，需统一关闭函数并核对组件能力；离开保护只拦截当前功能，不引入无关的全局导航限制。
- 保存期间禁止关闭和切换编辑记录，待请求完成后恢复；保存失败保留草稿。保存成功后更新基线并主动关闭，不再次询问放弃修改。
- 对话框里的选择尚未确认时也属于草稿；不要把候选勾选直接写入主表单。
- 取消编辑不能修改列表行或公共选项数据。初始化草稿时复制会被编辑的嵌套集合，不与展示数据共享可变引用。

## 关联编辑与选择

仅在业务需要角色、公司等关联关系时采用此结构：

- 编辑器使用具名 `defineModel` 接收关联集合；新增和移除只修改本地草稿，随主表单统一保存。取消主表单不应写入后端。需要独立保存的业务按其实际契约处理。
- 选择弹窗通过 `v-model:visible` 显隐，以 `excluded-*-ids` 排除已关联记录，并通过 `selected` 事件回传业务需要的字段。
- 按业务主键去重；不要混用关联记录 ID 与目标实体 ID。移除关联的确认文案应明确其含义，不能误导为删除实体。
- 复用已有列表 API 搜索和分页；仅允许选择有效记录时，优先使用后端状态筛选。前端过滤当前页时，不把过滤后的长度当作后端分页总数。
- 打开、重新查询、翻页和关闭时清理选择状态；默认采用当前页选择，不默认承诺跨页保留。
- 支持行点击切换勾选，空选择时禁用确认按钮；复选框、按钮等自身点击不能再触发行级切换，避免一次点击反向取消选择。
- 回传后主表单立即合并去重并更新排除集合；清空表格内部和业务数组中的选择，避免弹窗保留打开时重复添加。是否关闭弹窗按业务交互决定。

## 后端接口契约

下表中的 `/xx` 是单数资源路径；保留项目真实的 API 前缀。请求字段与响应包装以实际后端模型为准。

| 操作 | 方法与路由 | 前端处理 |
| --- | --- | --- |
| 列表 | `POST /xx/list` | 请求体为查询模型；读取分页展示数据 |
| 编辑详情 | `GET /xx/{id}` | 按 ID 获取完整表单与关联数据 |
| 新增、编辑 | `POST /xx/save` | 新增时 ID 为空或省略，编辑时传 ID |
| 启用 | `GET /xx/{id}/enable` | 独立 API 函数，成功后刷新 |
| 禁用 | `GET /xx/{id}/disable` | 独立 API 函数，成功后刷新 |
| 单删、批删 | `POST /xx/delete` | 请求体直接为 ID 数组；单删传 `[id]` |

编辑详情需要额外参数且参数总数超过两个时，按后端规范改为 `POST` 请求模型，并使用后端实际声明的路由。不要自行发明路由。

启用、禁用虽然按契约使用 `GET`，仍属于写入操作，应用提交锁和写入重试规则，不预加载、不缓存操作结果。批量响应若支持部分成功，明确显示成功与失败范围，只清理已成功项，不将整个批次提示为成功。

新增功能按上表对接。修改现有功能时先核对 Controller、OpenAPI 或已确认的接口定义，不单方面替换仍在使用的路由；发现差异时说明前后端需要协调的改动，不扩大为全项目接口迁移。

## 国际化、布局与样式

- 用户可见的标题、标签、占位符、确认文案与提示统一使用 `$t`。复用 `common.*`，业务文案放在对应 `page.manage.<domain>.*`，同步项目实际维护的语言文件与类型。
- 页面纵向排列搜索区与内容卡片，区域间距默认 `12px`；桌面下内容卡片占用剩余高度，窄屏允许页面滚动。卡片头部左侧显示标题，右侧排列工具栏。
- 表格使用边框、加载遮罩与稳定行标识。分页列表将分页器置于表格下方居中，间距约 `10px`；完整树表格占满内容区，无需预留分页空间。
- 编辑表单采用顶部标签，普通字段可用两列或三列栅格，长文本、页面选择或外链等较长字段独占一行；栅格间距使用 `16px` 或 `24px`，同一表单保持一致。输入框、选择器与数字输入尽量填满所属列。
- 默认编辑抽屉沿用 `#header` 插槽中的标题和小尺寸保存按钮，关闭使用 `ElDrawer` 内置按钮。菜单等现有复杂表单有 `:with-header="false"`、宽度 `min(100%, 1024px)` 的自定义头部实现，标题使用 `20px`、字重 `600`，与表单间距 `24px`；这属于业务特例，新增普通编辑抽屉不默认复制。确需沿用此结构时，自定义保存仍须使用 `ElPopconfirm`，并提供带国际化 `aria-label` 的关闭图标按钮。
- 样式优先复用 UnoCSS 工具类与项目公共 class；需要复杂布局时再使用局部 CSS。图标和文本对齐使用 flex，紧凑按钮组间距约 `8px`，头部操作间距约 `12px`。
- 文本列按内容左对齐，状态和操作列适合居中；若全局样式清除了单元格 padding，用局部 `:deep` 选择器补回左右约 `12px` 内边距，避免内容贴边，并检查树展开图标是否仍正常。
- 含关联表格的抽屉使用 `auto minmax(0, 1fr)` 分配表单与剩余区域；在抽屉 body、Tabs、TabPane 和表格容器高度链上设置必要的 `min-height: 0` 与 overflow，使表格内部滚动。
- 关联表格参考 `height="100%"` 与 `scrollbar-always-on`。样式优先 scoped；确需修改传送到外部的抽屉 body 时，用业务专属 class 限定全局选择器。
- 桌面布局可采用宽度 `60%` 的抽屉、`860px` 的弹窗和三列表单。按内容与窄屏适配宽度、栅格及滚动，确保按钮和表单可操作。

### 按钮样式与操作区

复用公共操作组件的按钮外观；自定义按钮按所在区域选用以下样式，避免同一操作区混用不必要的尺寸。

| 场景 | 样式与尺寸 | 排列与交互 |
| --- | --- | --- |
| 搜索 | `type="primary" plain size="small"` | 文本按钮，放在重置之前 |
| 重置 | 默认类型、`size="small"` | 文本按钮，与搜索同组靠右 |
| 列表新增 | `type="primary" plain size="small"` | 加号图标与文本 |
| 列表批量删除 | `type="danger" plain size="small"` | 删除图标与文本，空选择禁用，使用 `ElPopconfirm` 确认 |
| 刷新 | 默认类型、`size="small"` | 刷新图标与文本，加载时图标 `animate-spin` |
| 默认编辑抽屉保存 | `type="primary" size="small"` | 使用 `ElPopconfirm`，绑定保存 loading |
| 现有自定义大表单头部保存（业务特例） | `type="primary"`，默认尺寸 | 使用 `ElPopconfirm`，绑定保存 loading |
| 行操作入口 | 默认类型、`circle size="small"` | 编辑图标，悬停打开 `ElDropdown trigger="hover"`，下拉尺寸为 small；菜单项触发操作 |
| 关联表格单项移除 | `type="danger" link circle size="small"` | 删除图标，提供名称提示，移除前确认 |
| 关联编辑器新增 | `type="primary" size="small"` | 文本按钮，紧邻批量移除按钮 |
| 关联编辑器批量移除 | `type="danger" plain size="small"` | 空选择禁用，说明移除的是关联 |
| 选择弹窗确认 | `type="primary"`，默认尺寸 | 文本可附选中数量，空选择禁用 |
| 选择弹窗关闭 | 默认类型、默认尺寸 | 放在确认后，页脚按钮居中、间距 `12px` |
| 默认编辑抽屉关闭 | `ElDrawer` 内置关闭按钮 | 保留默认 `show-close`，位于头部右上角 |
| 自定义头部关闭（业务特例） | `text circle` | 使用关闭图标和国际化 `aria-label` |

- 列表卡片头部复用 `TableHeaderOperation`：绑定 `v-model:columns`、`disabled-delete` 与 `loading`，按需设置 `show-refresh`；处理 `add`、`delete`、`refresh` 事件。刷新默认显示，不需要时显式关闭。
- 公共工具栏用可换行的 `ElSpace` 靠右排列；自定义操作通过 `prefix`、`suffix` 插槽补充。替换默认插槽时，新增和批量删除的显示及确认行为由调用方负责。
- 公共工具栏已确认批量删除，页面事件处理函数不再重复确认。单行删除和状态切换使用 `ElMessageBox` 类确认流程；取消只退出操作，不能吞掉真正的请求异常。
- 下拉菜单项左侧带相应图标，图标与文本间距约 `4px`；删除项用 `text-error`，需要分组时添加分隔线。不要把所有行操作堆成多个实心按钮。
- 操作列默认遵循项目明确的悬停下拉约定，显式设置 `trigger="hover"`，不要擅自统一改为点击触发。任务明确要求触屏适配时，再按该页面需求补充交互；键盘操作与焦点样式按组件实际能力验证。
- 按钮图标使用组件 icon 插槽或 `ElIcon`，沿用项目图标尺寸；不为加号、删除、刷新单独硬编码配色。只有图标的按钮提供国际化标题或 `aria-label`。
- 保存的 loading 与重复提交拦截由保存请求状态控制；表格 loading 不应被误用为保存状态。公共刷新当前只旋转图标，不自动禁止重复点击，需要时在处理函数中限制。

### 配色与交互状态

- 使用 Element Plus 主题变量和项目语义工具类表达背景、边框、文字与状态，避免硬编码色值，确保浅色与深色主题均可读。
- 启用或成功使用 `success`，警示与隐藏状态可用 `warning`，中性类型与普通说明使用 `info`，主业务类型可用 `primary`。禁用状态沿用当前业务的 `warning`、`info` 或 `danger` 约定，不跨业务机械替换。
- 状态标签必须同时提供文案，不只依靠颜色。只读字段复用项目的只读样式，禁用和只读保持语义区别。
- 请求中显示相应区域的 loading；保存中显示按钮 loading 并阻止重复提交。空选择时禁用批量和确认操作，空数据沿用组件空状态，失败沿用统一消息反馈。
- 窄屏下表单降为单列或适当减少列数，抽屉宽度不超过视口，工具栏允许换行，宽表格在自身区域横向滚动。

## 生命周期与业务数据

- 若页面使用 KeepAlive，区分激活、失活和卸载；按项目约定恢复或刷新查询，避免重复注册监听器。失活时使不应继续写入界面的请求失效，并清理定时器、订阅和临时资源。
- 只有后端提供版本号或并发令牌时才接入并发更新校验；冲突时保留草稿，提示重新获取并合并，不静默覆盖他人修改。不自行创建与后端不匹配的并发字段。
- 业务文案默认按普通文本渲染；需要富文本或外链时复用项目已有的净化和协议校验机制，禁止直接渲染未经处理的 HTML 或执行任意协议链接。
- 密码、令牌和敏感详情不写入日志、URL、浏览器持久存储或成功提示；复用统一请求层，避免额外复制鉴权信息。

## 实施与验证

1. 明确查询字段、列表列、编辑字段、关联关系、权限和接口契约；仅缺少关键业务信息时询问。
2. 补齐 API 类型、请求函数及导出，再实现列表、抽屉和必要的关联组件。
3. 新页面检查路由、菜单、权限和国际化接入；遵循项目的路由生成机制，需要时运行 `pnpm gen-route`，不手工修改生成文件。
4. 读取当前 `package.json`，执行 `pnpm typecheck`，对修改文件运行 `pnpm exec eslint <文件路径>`；注意现有 `pnpm lint` 包含 `--fix`，避免无关文件被修改。影响构建或新增页面时运行 `pnpm build`。
5. 有可运行环境时检查搜索重置、分页、多选、新增、详情加载、保存、启禁用与删除；涉及关联时检查去重、移除、分页选择及取消后的数据隔离。树形功能还需检查展开收起、搜索祖先保留、父子选择、父级排除和删除后代的实际行为。确认抽屉滚动、窄屏布局与主题配色。
6. 核对真实网络请求的方法、路由、ID 类型和删除数组请求体；确认失败不提示成功、加载态恢复且表单内容保留。无法执行的检查如实说明，不把静态检查当作接口联调通过。

## 交付验收

仅对本次功能适用的项目进行检查，无关功能标为不适用。

| 验收范围 | 通过条件 |
| --- | --- |
| 接口与类型 | 真实请求的方法、路由、包装、ID 与保存字段匹配后端；列表与编辑数据分离 |
| 权限 | 有权限账号可操作；无权限账号的页面、按钮与直接入口受限制；后端拒绝时反馈正确 |
| 查询一致性 | 快速搜索、连续翻页和弹窗重开后显示最新结果；末页删除回退正确；适用时页面重新激活无旧请求覆盖 |
| 编辑完整性 | 新增重置、编辑详情、校验失败、未保存关闭及保存期间关闭行为正确，无草稿泄漏 |
| 写入结果 | 重复点击不重复提交；失败保留输入；清空字段和关联生效；写入成功但刷新失败时反馈准确，适用时覆盖部分成功与并发冲突 |
| 树与关联 | 层级、父级排除、搜索祖先、父子选择、删除影响与关联去重符合业务契约 |
| 界面 | 窄屏与项目实际支持的主题下可用；按钮、焦点、触屏操作与滚动无阻碍 |
| 工程检查 | 适用的类型检查、受影响文件 lint 和构建通过，生成内容无无关改动 |

交付说明受影响内容、已完成检查及其结果；把未执行项、失败项、原因和待协调契约明确列出。类型检查或文档检查通过，不代表接口联调、权限验证或生产验收通过。存在影响核心流程的失败项时，不能标记功能验收完成。

本技能首次用于实际业务时，选择一个获授权且包含权限、树形或关联选择、编辑保存的功能验证上述流程，记录产生的代码问题并据此修正规则。未完成这种实际试用前，只能说明技能文档已完善，不能宣称已验证稳定的生产交付能力。
